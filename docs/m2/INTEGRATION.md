## Trust and failure boundaries

`route_from_m1` takes an adapter, tenant pseudonym and feature. It binds returned authorization to that tenant, revalidates snapshots and converts exceptions into no-route. The adapter must be trusted in-process code; arbitrary callers must never provide authorization, policy or registry snapshots. Typed objects do not authenticate their contents. M1 must verify approval, independent evaluator identity, evidence integrity and snapshot provenance before construction. `source='independent'` is an assertion from that trusted boundary, not cryptographic certification.

M1 authorization must derive privacy from trusted tenant/task policy, never task hints. `allowed_models` is the final privacy, region, tenant and feature allow-list. Empty or unavailable authorization denies. `restricted_approved` is separate approval for restricted/high-stakes profiles. Feature strategy selection and tenant constraints must arrive through M1 policy resolution; tenant profiles cannot relax platform limits. Policy catalog rollback changes the active immutable version only to an approved enabled entry.

The adapter has no network implementation here. Any future remote adapter must impose deadlines before returning; a synchronous Protocol cannot forcibly terminate a stuck implementation. Errors and outage results fail closed. No permissive production adapter exists.

M2 uses `budget_remaining` as a conservative eligibility ceiling against all allowed attempt charges. It neither reserves funds nor records actual spend. M3 must obtain a fresh atomic M1 financial reservation and independent execution authorization before any inference or tool activity. Concurrent recommendations cannot spend that shared budget. All decisions have `execution_authorized=false`; importing `routing` cannot invoke `execution.Adapter`.

## Replay and retention

Persist trusted input snapshots in an access-controlled M1 evidence store keyed by digest/version, outside these pure modules. Decision records include sanitized task metadata, policy, authorized tenant pseudonym, model/evidence/price versions, reason codes and canonical snapshot digest. Reproduction requires the original immutable snapshots and explicit clock/correlation input; versions alone are not an archive. Unknown category strings are discarded from audit output. Correlation IDs and tenant pseudonyms must be generated by the trusted caller; do not encode personal content in them.

No raw prompt, customer data, provider pricing claims or model self-confidence are used. Demo evidence is explicitly synthetic and rejected outside explicit simulation. Task taxonomy v1 rejects unsupported schema versions; no implicit migration guesses.

## M3 / M4 gates

M3 can consume typed recommendations for development only. Live integration remains HOLD until M1 registry/privacy/evidence/budget adapters are implemented and separately approved. M4 must deliver independently evaluated per-task/model-version outcomes, sample sizes, observed charges, latency and freshness. No external benchmark or current provider price was invented. Production readiness also requires evidence retention, authenticated transport, financial reservation and separate owner approval; M2 does not certify these dependencies.
